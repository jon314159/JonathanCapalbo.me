# Arcade Operations Ticketing Modernization

## Portfolio disclosure

This is a self-directed, hypothetical business-analysis case study. The arcade, stakeholders, operating data, requirements, user stories, tests, targets, and implementation materials are fictional or simulated. ServiceNow is used only as a conceptual platform frame; no ServiceNow instance was configured, built, tested, or deployed.

## Business problem

The simulated single-location arcade relies on inconsistent verbal, paper, and message-based handoffs for broken machines, game-card issues, refunds, prize-counter problems, and facility incidents. The result is limited ownership visibility, inconsistent prioritization, incomplete records, and weak reporting.

## Recommended scope

Design a unified internal ticketing pilot for all five issue categories at one location. The proposed operating model standardizes intake, routes work by category and urgency, applies approval controls, records status history, verifies resolution, and defines a reporting baseline. Emergency response always takes priority over ticket entry.

## Analyst deliverables

- Problem statement, project charter, stakeholder analysis, and scope
- Simulated current-state and proposed future-state workflows
- 110 draft functional, data, reporting, security, and nonfunctional requirements
- 34 user stories with 102 Given/When/Then acceptance criteria
- 111-field data dictionary with 20 cross-field validation rules
- Requirements traceability through 31 planned UAT cases
- Implementation and cutover plan, employee procedure, and governance model
- 16 KPI definitions and three report specifications

All 31 UAT cases remain **Not Executed**. No implementation outcomes, time savings, adoption results, or operational improvements are claimed.

## Proposed lifecycle

`Safety first → Minimum ticket → Triage and ownership → Work or approval → Pending if blocked → Resolve → Verify → Close and report`

## ServiceNow positioning

The platform mapping is conceptual. It uses official ServiceNow material to distinguish incidents, request/catalog patterns, work orders, and workplace services. A real implementation would require discovery, platform-owner review, licensing decisions, security and privacy review, configuration, integration design, and testing.
