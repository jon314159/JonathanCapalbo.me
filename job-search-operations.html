Private Job-Search Operations System.

The operational problem

Keep each step tied to the right job and evidence.

A job can appear on several boards, a source can fail to load, and an interrupted application can leave its status unclear. Repeating the whole process adds work; trusting an old result can carry an error into the next step.

I customized the workflow around explicit records and review points: identify duplicates, preserve source evidence, check the current resume, and distinguish a prepared application from a confirmed submission.

Workflow controls

Checks at the points where errors can carry forward.

Consolidate discovery

Normalize job links and compare identities before fetching more detail. Preserve source aliases and conflicting metadata so a duplicate check does not erase useful evidence.

Verify the source

Keep the posting snapshot, source, and check time together. Treat a blocked or malformed response as an unresolved check; it does not establish that a job is closed.

Check the resume

Check page count and text extraction, then review the rendered PDF and factual claims. Reuse verification only while the relevant document and evidence inputs remain unchanged.

Record the actual outcome

Keep prepared and submitted materials separate. Require submission confirmation before marking a role applied, and preview tracker changes before saving them.

Synthetic examples

How the controls change the next step.

These examples illustrate the workflow. They contain no real employers, applications, or test results.

The same opening appears twice

Two source links identify the same role. The workflow consolidates the discovery records while retaining both source references for review.

A posting cannot be retrieved

The source check remains unresolved. The workflow records the failure and uses its recovery rules rather than labeling the employer unavailable or the job closed.

A resume changes after verification

The previous check no longer covers the changed file. The affected verification steps must run again before that version is used.

The submission result is uncertain

The application stays unconfirmed until the portal status is checked. Recovery starts with that status check rather than another submission.

Maintenance and evidence

Document the change and check what it affects.

The local Git history records changes to staged application processing, discovery and ranking evidence, checkout consistency, and network-error handling. The repository includes automated checks for these behaviors.

I use the system for my own job search. The project demonstrates workflow organization, data validation, exception handling, and implementation support as independent work.
